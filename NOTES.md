## 2. YAML Config Parser Not Implemented

**Affected files:** `src/main.cpp`, `src/train_main.cpp`

Both executables currently hard-code hyperparameters (image size, thresholds,
model path) instead of reading from `config/config.yaml` or
`config/training_config.yaml`.

**What must be added:**  
A YAML parsing step using a library such as:
- [yaml-cpp](https://github.com/jbeder/yaml-cpp) (most common on Windows)
- [mini-yaml](https://github.com/Cant-Stop-Programming/Mini-yaml)

**Steps to integrate yaml-cpp:**
1. Install: `vcpkg install yaml-cpp` or download source.
2. Add to `CMakeLists.txt`:
   ```cmake
   find_package(yaml-cpp REQUIRED)
   target_link_libraries(${PROJECT_NAME} PRIVATE yaml-cpp)
   ```
3. Replace hard-coded values in `main.cpp` with YAML lookups, e.g.:
   ```cpp
   #include <yaml-cpp/yaml.h>
   YAML::Node cfg = YAML::LoadFile(configPath);
   int imageWidth = cfg["img_config"]["input_size"][0].as<int>();
   ```

## 3. ModelTrainer — Duplicate CNN Architecture Definition

`train_main.cpp` defines `DefectNetImpl` locally (lines ~282–363), and
`ModelTrainer.cpp` defines an *identical* anonymous `DefectNetImpl` struct.
This causes a **ODR (One Definition Rule) violation** if both translation
units are linked.

**Fix required:**  
1. Move the canonical `DefectNetImpl` definition into `include/CNNModel.h`
   (or a dedicated `include/DefectNet.h`).
2. Delete the duplicate definitions from both `train_main.cpp` and
   `ModelTrainer.cpp`.

## 6. `ctime_s` in `include/Visualizer.h` — Windows-Only

`VisualData::getCurrentTimestamp()` uses `ctime_s()`, which is a
Microsoft-extension safe function (available in MSVC). On GCC/Clang (Linux/macOS),
this function does not exist and must be replaced with:

```cpp
// Cross-platform alternative
char buffer[26] = {0};
std::strftime(buffer, sizeof(buffer), "%Y-%m-%d %H:%M:%S", std::localtime(&now_c));
```

## 9. Model File Format — `.pth` vs `.pt`

The original config referenced `models/best_model.pth`. The C++ inference
pipeline (`CNNModel::LoadModel`) only accepts **TorchScript** (`.pt`) models.
Standard PyTorch training saves `.pth` checkpoint files (Python pickles),
which **cannot** be loaded by `torch::jit::load()`.

**Required workflow to produce an inference-ready `.pt` model:**
```python
# In Python, after training:
import torch
model = YourModel()
model.load_state_dict(torch.load("best_model.pth"))
model.eval()
scripted = torch.jit.script(model)
scripted.save("models/defect_model.pt")
```
Or use `torch.jit.trace()` with a sample input tensor.
